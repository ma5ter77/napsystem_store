# Аудиостудия NAP (ТЗ аудиоплатформы v2.1, этап M1)

Аудиостудия встроена в магазин: она находится в кабинете автора («Кабинет разработчика → Открыть аудиостудию»,
`/{ru|en}/developer/studio`). Отдельного приложения нет, используются те же учётные записи, хранилище файлов,
очередь заданий и дизайн-система. Архитектура и план этапов M2–M6 — в docs/architecture/audio-platform.md.

## Что умеет M1

| Возможность | Как устроено |
|---|---|
| Неизменяемые исходники | WAV/FLAC/AIFF, 1–8 каналов, до 3 ч. При загрузке обязательны происхождение и права. Файл хранится как есть (`assets.kind = studio_source`, `immutable`), SHA-256 проверяется при приёме и показывается в библиотеке. Проект ссылается на файл, а не копирует его |
| Проект | 2, 3, 6 или 8 логических шин (NEURO_L/R, VOICE_CENTER, MUSIC_L/R, LFE, BACK_L/R); 44,1/48/88,2/96 кГц; 16/24-бит PCM или 32-бит float. Состояние — JSON, всё время в целых сэмплах |
| Редактор | дорожки по шинам, клипы с waveform, перетаскивание и обрезка краёв, привязка к сетке, масштаб, mute/solo, усиление, явные fade in/out, разрезание, отмена/повтор (200 шагов), горячие клавиши |
| Генераторы | бинауральный (пара на нейро Л/П, разница частот — ритм; линейная автоматизация Δ с непрерывной фазой) и изохронный (импульсы с косинусными фронтами без щелчков). Отсчёты — замкнутая формула от номера сэмпла: любое разбиение на блоки даёт те же данные |
| Автосохранение | PATCH с `base_revision`; если проект изменили в другой вкладке — 409 `revision_conflict` и предложение загрузить последнюю версию, правки не затираются молча |
| Предпросмотр | сервер рендерит окно до 60 с тем же кодом, что и экспорт; браузер играет его через один `AudioContext` с частотой проекта и дискретными каналами. Показываются реальное число выходов устройства и предупреждение, если браузер будет сводить каналы |
| Экспорт | снимок ревизии → задание в очереди (lease, повторы, отмена, восстановление после падения обработчика) → WAV WAVE_FORMAT_EXTENSIBLE с маской каналов → независимая проверка → отчёт и скачивание по подписанной ссылке |
| Профили | HEADPHONES_2_0 (0x3), NAP_ACOUSTIC_3_0 (0x7, FL/FR/FC — не 2.1), NAP_CHAIR_5_1 (0x60F, нейро на SL/SR), NAP_PRO_7_1 (0x63F). Порядок каналов и матрица видны до запуска экспорта; шины, которых нет в профиле, названы предупреждением |

### Никакой скрытой обработки
Нет нормализации, лимитера, эквалайзера и дизеринга. Клип с 0 dB копируется бит в бит (тест T02). Перегрузка —
ошибка: файл не создаётся, отчёт называет канал, число сэмплов и первый сэмпл. Жёсткое ограничение включается
только явно («Разрешить жёсткое ограничение»), отсечённые сэмплы считаются в отчёте. Если частота исходника
отличается от проекта, применяется SoX (soxr) и это записывается в отчёт (`processing.src`).

### Отчёт экспорта
Формат, раскладка, маска, порядок каналов, SHA-256; по каждому каналу — пик, true peak (на 44,1/48 кГц), RMS,
«тишина», число отсечённых сэмплов. Проверка читает записанный файл заново: `wave` из stdlib (или разбор RIFF для
float) и ffprobe для раскладки; совпадение длины, каналов, частоты, разрядности и SHA-256 — «пройдена».

## Демо-сценарий (5 минут)

1. Войти автором (`dev1@nap.demo` / `demo-password-1` на локальном или превью-стенде; на публичном сервере пароль свой, см. docs/vps-deploy.md) → «Кабинет разработчика» → «Открыть аудиостудию».
2. «Загрузить исходник»: любой WAV с голосом, указать происхождение и права. В библиотеке появятся кодек, каналы,
   частота, разрядность и SHA-256.
3. «Новый проект» → «6 — нейро, голос, музыка, LFE» → «Создать проект».
4. Выбрать дорожку «Голос» → «Добавить» у исходника. Нажать «Бинауральный» — на нейро Л/П появятся клипы 196/204 Гц.
5. Выбрать клип генератора, в «Ритм» ввести 6 — метки клипов станут 197/203 Гц; статус «Сохранено · ревизия N».
6. «Слушать» — предпросмотр с позиции курсора (в наушниках: профиль «Наушники 2.0»).
7. Экспорт: профиль «Кресло NAP 5.1» → «Экспортировать WAV». В отчёте: голос в FC, нейро в SL/SR по −18 dBFS,
   FL/FR/LFE — тишина, проверка пройдена. «Скачать WAV».

## Команды

```bash
# backend: тесты студии (T01–T09, API, preview = export, доступы, восстановление)
cd backend && uv run pytest tests/test_audio_studio.py -q
# frontend: unit-тесты модели редактора, проверки
cd frontend && npm run test-studio && npm run typecheck && npm run check-i18n
# браузерный сценарий против запущенного стенда (как в CI)
cd frontend && BASE=http://localhost:3000 node e2e/studio.cjs
```

## API (`/api/v1/audio`, роль developer, только свои объекты)

| Метод | Путь | Назначение |
|---|---|---|
| POST / GET | `/assets`, `/assets/{id}`, `/assets/{id}/waveform` | загрузка (тикет + PUT `/uploads/{token}`), список, метаданные, пики |
| POST / GET / PATCH | `/projects`, `/projects/{id}` | создание, список, чтение, сохранение с `base_revision` |
| POST | `/projects/{id}/revisions` | неизменяемый снимок (повторно не создаётся, если состояние не менялось) |
| POST / GET | `/projects/{id}/renders` | экспорт (`Idempotency-Key`), история экспортов |
| GET / POST | `/render-jobs/{id}`, `/render-jobs/{id}/cancel`, `/render-jobs/{id}/download` | статус и отчёт, отмена, подписанная ссылка |
| GET | `/routing-profiles` | профили с матрицей и порядком каналов |
| POST | `/projects/{id}/preview` | WAV-окно ≤ 60 с, заголовок `X-Render-Path: export-identical` |

## Ограничения M1 (честно)
- WAV ограничен 4 ГиБ (≈ 3,5 ч 8 каналов 24/48); RF64 и FLAC-экспорт — M2.
- Браузер не гарантирует bit-perfect воспроизведение; источник истины — экспортированный файл и его отчёт.
- Калибровка выходов, пользовательские профили и Channel Router — M2; публикация, подписка и защита контента — M3–M5.
