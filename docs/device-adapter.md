# DeviceAdapter, проигрыватель, сеансы, анкеты и измерения

Код: `backend/app/adapters/devices.py`, `services/sessions.py`, `frontend/app/[locale]/play/[slug]/page.tsx`.

## Контракт

```
connect · disconnect · getCapabilities · prepareSession · start · pause · resume · stop · getStatus · события
```

Capabilities: модель, firmware/API, sample rates, аудиовыходы, разделение каналов (`verified_hardware` | `user_confirmation_required` | `none`), датчики, функции, пределы параметров, флаг `simulated`. Из них выводится набор `provides` (`stereo_output`, `stereo_separation`, `vibroacoustic_output`, `heart_rate_sensor`, `hrv_sensor`), который сравнивается с `required_capabilities` и `min_api_version` из manifest.

Реализации:
- `SimulatedDeviceAdapter` — профили `sim-chair-v1` (наушники + виброакустика, разделение «подтверждено устройством», датчики пульса/HRV — синтетические), `sim-speakers` (стерео без разделения — несовместим с бинауральными программами), `sim-legacy-api` (API 0.9).
- `WebPlayerController` — проигрыватель в браузере: разделение каналов требует подтверждения наушников и L/R-теста пользователем; это явно помечается как самопроверка, а не аппаратное измерение изоляции.
- `NapChairAdapter` — заглушка: без документации производителя реальные команды не выдумываются, любой вызов → `device_protocol_unavailable`.

## Сеанс

`created → precheck → ready → running ↔ paused → completed` (+ `cancelled`, `failed`). Анкеты отдельно: `pending / completed / skipped`.

- Сервер проверяет доступ (entitlement), закрепляет сеанс за **опубликованной версией** и её аудиоартефактом, выдаёт разрешение: короткую подписанную ссылку, SHA-256, параметры воспроизведения (`channels=2`, без даунмикса, без crossfeed, без перестановки каналов). Истёкшая ссылка → `POST /sessions/{id}/grant` с повторной проверкой прав.
- Несовместимая capability блокирует создание/подготовку с перечнем причин.
- Команды: `command_id`, `expected_version`; повтор с тем же `command_id` возвращает сохранённый результат (`replayed`), устаревшая версия → `version_conflict`; одно устройство — максимум один активный сеанс (частичный уникальный индекс).
- События: ID, последовательность, время возникновения и получения; дедупликация по `(session, event_id)` и `(session, seq)`; контроллер сообщает фактическое состояние (`state: completed|cancelled`), старые команды после восстановления связи не выполняются заново.

## Веб-проигрыватель

Запуск только по действию пользователя; трек загружается целиком, SHA-256 сверяется до воспроизведения, декодирование в `AudioContext(48000)` с `channelInterpretation="discrete"`; проверяется, что каналов ровно 2. Локальная остановка работает всегда, в т.ч. без сети. События пишутся в локальную очередь (`localStorage`) и отправляются, когда сеть доступна; сервер дедуплицирует. Ограничения: закрытие вкладки прерывает сеанс; браузеры могут приостанавливать таймеры фоновых вкладок (позиция при этом считается по часам `AudioContext`); запуск нового платного сеанса офлайн не поддерживается.

## Оценка состояния и измерения

- Анкета `state-v1` до/после (расслабленность, напряжение, бодрость, 0–10), необязательная, можно пропустить. Показываются ответы и простая разница — без «медицинских индексов».
- Измерения: тип (`self_report`, `heart_rate`, `hrv_rmssd`, `eeg`), метрика, значение, единица, время, источник, качество, версия расчёта, флаг `synthetic`. Единицы проверяются по типу (HRV — только мс, никогда не «альфа-активность»); ЭЭГ в MVP не принимается.
- Хранение только с согласием (`consents`, срок хранения настраивается, задача очистки по сроку); удаление по запросу пользователя. Без согласия ответы не сохраняются (сохраняется только статус).
- Сервер не создаёт измерений сам; данные симулятора обязаны быть помечены `synthetic=true`; прерванный сеанс не получает вымышленных значений.
- Разработчик получает только агрегаты; группы меньше 5 человек скрываются.
