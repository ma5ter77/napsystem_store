# Версии технического задания

Каждая версия ТЗ хранится отдельным неизменяемым файлом `TZ-vX.Y.md`. Действующая версия и её связь с версиями продукта записаны в `release.json` (корень репозитория) и показываются на странице продукта «О версии» (`/ru/about`, `/en/about`) и в `GET /api/v1/version`.

## Нумерация

| Изменение | Пример | Номер |
|---|---|---|
| Новая область, отказ от области, смена модели денег или ролей | добавить смешанный checkout | **X+1.0** |
| Новые требования или уточнения внутри существующих областей | налоги в заказах, новый статус | **X.Y+1** |
| Редакторская правка без изменения смысла | опечатка, формулировка | правка в том же файле запрещена: ошибки фиксируются в следующей minor-версии |

Отправленная версия не редактируется. Новая версия начинается с копии предыдущей и раздела «Изменения относительно предыдущей версии».

## Процесс

1. Изменение предлагается задачей в бэклоге с типом **«ТЗ»** (ссылка в `docs/BACKLOG.md`).
2. После согласования создаётся `TZ-vX.Y.md` со статусом `черновик`, в шапке перечисляются задачи бэклога, которые его породили.
3. Владелец продукта утверждает: статус `утверждено`, дата, запись в таблицу ниже и в `release.json → spec`.
4. Задачи на реализацию получают ссылку на раздел новой версии ТЗ; релиз продукта, закрывший их, указывает `implements` = эта версия.

## Статусы

`черновик` → `утверждено` → `принято в работу` → `реализовано` (или `заменено` версией X.Y).
