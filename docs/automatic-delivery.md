# Автоматическое принятие и доставка

Разрешено владельцем 01.11.2026 для **ma5ter77** в BrothersB/nap-store.

1. Иван создаёт обычный, не draft PR из ветки этого репозитория в master.
2. Автомат проверяет настоящий GitHub-логин автора, актуальность ветки относительно
   master и успешный CI именно последнего коммита. Для изменений выпуска требуется
   также release-acceptance. Ошибки, конфликты и устаревшие ветки не принимаются.
3. PR сливается merge-коммитом с сохранением истории. Фиктивный человеческий review
   не создаётся. После merge явно запускается CI master: обычный push-триггер
   после изменения от GITHUB_TOKEN не срабатывает.
4. Успешный CI текущего master автоматически доставляет git archive в новую папку
   /srv/nap-store/incoming/github.*. Старые архивы и исходники не перезаписываются.
   GitHub Actions показывает SHA, SHA-256 и путь в summary.

Для обновления ветки Иван может влить origin/master и повторно push. Draft не
принимается; ready-for-review запускает повторную проверку уже имеющихся результатов.
Автомат работает по событиям, без платного GitHub auto-merge и без ожидания владельца.
Лимиты минут Actions бесплатного тарифа продолжают действовать.
В private Free это правило автоматизации, а не принудительная защита от прямого push
пользователя с write: договорённость — изменения через PR.

## Граница автоматизации

**UPLOADED_NOT_INSTALLED** означает только проверенную доставку исходного архива.
Магазин пока не развёрнут. Автоматический запуск, миграции, nginx/DNS и основная
платформа не входят в этот механизм. Для запуска нужны подготовленный runtime,
секреты приложения, бюджет ресурсов, проверка изоляции и отдельный обработчик выпуска.
На сервере 4 ГиБ общей RAM, около 3,1 ГиБ available. Порог 4 ГиБ available у текущего
release controller — консервативный предварительный guard, не измеренный минимум.
SSH и доставка архивов такого порога не требуют. Не увеличивать тариф автоматически.

## Доступ автомата

Отдельный ключ STORE_UPLOAD_SSH_KEY в Actions secrets; публичный host key в
STORE_UPLOAD_HOST_KEY. Это не ключ Ивана и не root. Сервер разрешает только команду
upload-v1 через root-owned receive-upload.py, максимум 64 МиБ, тайм-аут 300 секунд.
Архив не распаковывается и не выполняется. Все имена генерирует принимающая сторона,
SHA/размер проверяются. При сбое partial сохраняется и не считается принятым архивом.
Для остановки доставки отключить deliver-source.yml либо удалить только отдельный
автоматический ключ из authorized_keys. Для остановки принятия отключить auto-accept.yml.
Не удалять ключ Ивана, данные, старые архивы или весь authorized_keys.
