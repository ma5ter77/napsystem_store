# Бинауральный конвертер

Код: `backend/app/dsp/engine.py` (генератор, измерители), `media.py` (ffprobe/ffmpeg), `pipeline.py` (этапы), `services/conversion.py` (очередь и состояния). Версия движка: `nap-binaural-engine/1.0.0`.

## Принцип

Исходная речь/музыка сохраняется, к ней добавляется **отдельный** слой из двух синусоид: левая несущая только в левом канале, правая — только в правом. Спектр не сдвигается, скорость и высота не меняются, генеративные модели не используются.

```
fL = carrier_center_hz − beat_hz/2          fR = carrier_center_hz + beat_hz/2
phaseL[n+1] = (phaseL[n] + 2π·fL/Fs) mod 2π  (float64, состояние переносится между блоками)
outL = 10^(source_gain_db/20)·sourceL + 10^(tone_gain_dbfs/20)·envelope·sin(phaseL)
```

`tone_gain_dbfs` — пиковый уровень каждого синуса до общего выходного gain. Огибающая — sin²-рампы, начинается и заканчивается ровно нулём; если файл короче суммы рамп, обе сокращаются пропорционально. В MVP частоты постоянны; при добавлении переходов частота будет интегрироваться в фазу (а не `sin(2π·f(t)·t)`).

Профиль `alpha-demo-v1`: центр 255 Гц, разница 10 Гц (250/260), исходник −6 dB, синус −30 dBFS, рампы 0,5 с. Это настройки цифрового QA, а не терапевтическая доза. Профили версионируются (`dsp_profiles.slug+version`), изменение создаёт новую версию, задание хранит снимок профиля. Собственный DSP-код и FFmpeg-фильтры из формы не принимаются: админ задаёт ровно 6 числовых параметров с проверкой диапазонов.

## Этапы задания

`queued → validating → decoding → rendering → quality_check → packaging → completed` (+ `failed`, `canceled`)

1. **validating** — размер (≤ 1 GiB), пустой файл, ffprobe по содержимому (а не по расширению): WAV PCM / FLAC / MP3 / M4A (AAC/ALAC); есть аудиопоток; каналов ≤ 2; длительность ≤ 120 мин; проверка места на диске под декодированный поток (а не размер MP3).
2. **decoding** — ffmpeg → float32 48 кГц (soxr precision 28, без дизеринга) во временный spool; `-xerror`, любые ошибки декодера, NaN/Inf и недодекодированный хвост (< 98 % ожидаемой длительности) → `decode_failed`/`truncated_audio`. Моно дублируется в оба канала, стерео сохраняется.
3. **rendering** (проход 1) — поблочно (65 536 кадров) рендер в float64; измерение true peak (4× oversampling, полифазный FIR 128 отводов с сохранением состояния), интегральной громкости BS.1770-4 (K-weighting, блоки 400 мс с перекрытием 75 %, гейты −70 LUFS / −10 LU), запись изолированного слоя первых 60 с для QA.
4. **quality_check** — анализ слоя на стационарном участке: частоты L/R, разница, подавление противоположной несущей; расчёт **одного общего** gain для обоих каналов, чтобы true peak ≤ −1,2 dBTP (потолок −1 dBTP минус допуск измерителя 0,2 dB). Компрессии, лимитеров, раздельной нормализации и автоподъёма до LUFS нет.
5. **packaging** (проход 2) — повторный детерминированный рендер с общим gain, квантование в 24 бит (округление, без дизера), запись мастера WAV PCM 24 bit / 48 кГц / stereo, повторное измерение true peak мастера и клиппинга; доставочный FLAC 24 bit (проверяется побитная идентичность PCM мастеру), превью FLAC первых 30 с, QA-отчёт JSON и параметры JSON с SHA-256 входа и выходов, версиями профиля, движка и инструментов.

Результат открывается **атомарно**: все объекты сначала загружаются, затем в одной транзакции под блокировкой строки задания создаются записи `assets` и ставится `completed`. Если задание уже отменено — загруженные объекты удаляются. `CHECK ((state='completed') = (result IS NOT NULL))` исключает частичный результат.

## Очередь, отмена, сбои

- Идемпотентность: уникальный `(owner_id, idempotency_key)`; повтор возвращает то же задание, другой источник/профиль с тем же ключом → `409`.
- Lease: worker захватывает задание `UPDATE … WHERE state='queued' OR lease_expires_at < now() RETURNING`; каждое обновление прогресса продлевает lease и проверяет владельца.
- Отмена ставит `canceled` под блокировкой строки сразу; worker на ближайшей проверке (раз в 0,5 с) получает `Cancelled`, убивает группу процессов ffmpeg и удаляет временный каталог. Гонка отмены и завершения даёт ровно одно конечное состояние.
- Временные ошибки (`internal_error`, таймауты, нехватка диска) повторяются до `max_attempts` (3); повреждённый файл автоматически не повторяется. Потерянный worker обнаруживается по истёкшему lease (`recover_expired_leases`), повтор начинается заново в новом каталоге. Ручной «повтор» создаёт новое задание (`retry_of`).
- Изоляция: только массивы аргументов (без shell), `-protocol_whitelist file,pipe`, ключи объектов генерирует сервер; для процессов ffmpeg — `RLIMIT_CPU`, `RLIMIT_AS`, `RLIMIT_NOFILE`, отдельная сессия процессов; каталог на задание и попытку; media-worker в docker compose — только во внутренней сети, с лимитами CPU/памяти. Серверное скачивание пользовательских URL отсутствует.

## Проверки (автотесты `backend/tests/test_dsp.py`, `test_jobs.py`)

| Проверка | Метод | Результат |
|---|---|---|
| Частоты 250/260, разница 10 Гц, допуск ≤ 0,1 Гц | окно Blackman-Harris-4, FFT с 8× дополнением нулями, квадратичная интерполяция лог-пика, сегмент 10 с | ошибка < 0,001 Гц |
| Подавление противоположной несущей ≥ 60 dB | DTFT с тем же окном на частоте противоположной несущей | > 180 dB (изолированный слой) |
| Поблочно = непрерывно, ≤ 1e-6 до квантования | случайные размеры блоков против однократного рендера и замкнутой формулы `sin(2πfn/Fs)` | ≤ 1e-6, сбросов фазы нет |
| Число отсчётов, NaN/Inf, клиппинг, TP ≤ −1 dBTP | 44,1/48 кГц, моно/стерео; громкий шум 0 dBFS | все выполнены, общий gain < 0 |
| Слой выключен → исходник сохранён | gain 0 dB, `tone_gain_dbfs=null`, 48 кГц | разница ≤ 2 LSB 24 бит |
| Воспроизводимость | двойной прогон | идентичный SHA-256 PCM |

Технические проверки подтверждают параметры сигнала. Достижение какого-либо состояния мозга ими не подтверждается и в интерфейсе не обещается.
