# Интеграция магазина с платформой NAP SYSTEM — открытые вопросы

Статус: **черновик для согласования**, ничего из этого не реализовано и не подключено. Основание — раздел 6 инструкции владельца от 31.10.2026.

Магазин (store.napsystem.com, BrothersB/nap-store) и платформа (BrothersB/nap-trainer) — отдельные системы с отдельными базами. Магазин не подключается к БД платформы и не копирует её пользователей.

## Что нужно решить до интеграции реальных данных

1. **Контракт API (версионированный, например `/integration/v1`).**
   - Что платформа получает от магазина: покупки, права доступа к программам, отзывы?
   - Что магазин получает от платформы: устройства пользователя, профили кресел, результаты сеансов?
   - Формат ошибок, коды, пагинация.
2. **Аутентификация сервисов.** Подпись запросов HMAC с общим секретом либо mTLS. Ротация ключей. Секреты хранятся только в окружении серверов.
3. **Идемпотентность и повторная доставка.** Ключ идемпотентности у каждого изменения; события через outbox (в магазине уже есть) с повторами и дедупликацией на приёме.
4. **Общий вход (SSO).** Автоматически от поддомена он не возникает. Варианты:
   - (а) отдельные аккаунты, как сейчас;
   - (б) вход через платформу по OAuth 2.0 / OIDC — магазин как клиент;
   - (в) общий провайдер.

   Cookies магазина остаются host-only; расширять `Domain` на `.napsystem.com` без отдельного анализа нельзя.
5. **CORS/CSRF**, если браузер платформы будет вызывать API магазина: только точные origin платформы, `credentials` по необходимости, без `*`, CSRF-токен для изменяющих запросов. Сейчас CORS выключен.
6. **Адрес платформы.** В документах — napsystem.ru, желаемый — napsystem.com. Миграция не подтверждена, origin нужно уточнить у владельца.
7. **Оплаты.** Кто продавец (merchant of record), один или два платёжных аккаунта, возвраты и споры. Связано с задачами NAP-012 и NAP-064 бэклога. До решения — только тестовый режим.
8. **Устройства.** Протокол кресла NAP SYSTEM (NAP-015): адаптер в магазине или вызовы через платформу.

## Предложение по порядку

1. Согласовать пункты 1–3 и 6.
2. Сделать эндпоинт «право доступа пользователя к приложению» в режиме только чтения с подписанными запросами — на тестовых данных.
3. Затем — SSO (пункт 4) и оплаты (пункт 7) отдельными задачами.
