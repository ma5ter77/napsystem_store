## Как изменения попадают на сервер

```
ветка → pull request → CI (тесты, e2e, Docker, сборка под Arm, vps-acceptance)
      → автопринятие в master → CI master → (последний шаг CI) deliver-vps:
        сборка образов amd64 + arm64 → GHCR по digest → SSH ключом, который умеет только napdeploy.py
        → дамп БД → миграции → переключение → проверка готовности → при ошибке возврат предыдущего выпуска
```

На сервере ничего не собирается, ключи и пароли в GitHub не попадают. Первая выкладка после merge идёт сама,
ручной запуск — **Actions → deliver-vps → Run workflow** (можно указать любой коммит с зелёным CI).
Время: CI 10–15 мин, образы 2–4 мин, выкладка 1–2 мин.

## Частые действия

| Задача | Как |
|---|---|
| Состояние сервисов, место, память | Actions → **store-ops** → `status` |
| Логи сервиса | store-ops → `logs` + сервис |
| Перезапуск (после правки настроек) | store-ops → `restart` |
| Откат на предыдущий выпуск | store-ops → `rollback` |
| Резервная копия сейчас | store-ops → `backup` |
| Изменить настройки | `ssh root@2.31.171.3`, затем `sudo -u napdeploy nano /srv/nap-store/shared/.env`, потом store-ops → `restart` |

Подробно и на случай аварий — [OPERATIONS.md](OPERATIONS.md).

## Переход из демо в боевой режим (чек-лист)

1. В `shared/.env`: `NAP_ENV=production`, `NAP_SEED_DEMO=0`. Демо-данные из базы удаляются отдельно,
   по согласованию: это необратимо.
2. Платежи: `NAP_PAYMENT_PROVIDER=stripe`, `NAP_STRIPE_SECRET_KEY`, `NAP_STRIPE_WEBHOOK_SECRET` — вписывает
   владелец на сервере (docs/stripe.md).
3. Почта: `NAP_EMAIL_BACKEND=smtp` и параметры SMTP-провайдера.
4. Юридические документы — под компанию и страну продажи (NAP-062).
5. Бэкапы во внешнее хранилище и внешний мониторинг (OPERATIONS.md, «Что ещё не сделано»).
6. store-ops → `restart`, затем проверить `/api/v1/ready` и тестовую покупку.

## Правила, которые держат систему целой

- Миграции только **совместимые назад**: добавить можно сразу, удалить старое — следующим выпуском.
  Откат меняет код, но не схему базы.
- Перед каждой выкладкой делается дамп базы (`backups/pre-deploy-*.dump`, последние 5).
- Секреты не пересылаются в чат, почту или GitHub-комментарии. Новые секреты создаются на сервере.
- Платные ресурсы (хранилище, сервер крупнее, сторонние сервисы) — только с согласия владельца.
