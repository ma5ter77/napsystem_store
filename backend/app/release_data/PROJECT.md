## Что это

NAP Store — маркетплейс по модели App Store для нейроакустической платформы NAP SYSTEM. Авторы аудиокниг, медитаций, музыки и курсов загружают аудио, готовят его бинауральным конвертером, собирают программу сеансов и публикуют её после модерации. Покупатели приобретают доступ или подписку, проходят сеансы на совместимом оборудовании и покупают кресла, наушники и комплекты с международной доставкой. Доход по цифровым продажам делится 70 % автору и 30 % платформе; оборудование продаётся по отдельной политике.

## Для кого

| Роль | Что делает в продукте |
|---|---|
| Гость | смотрит каталоги, карточки, публичные фрагменты |
| Покупатель | покупки, подписки, библиотека, сеансы, анкеты, заказы оборудования |
| Разработчик (автор) | приложения, загрузка аудио, конвертация, версии, цены, доходы, SDK-ключи |
| Поставщик и оператор исполнения | заказы, комплектация, посылки, доставка, возвраты, склад |
| Модератор | проверка версий и товаров |
| Администратор | роли, профили DSP, финансы, выплаты, аудит, эксплуатация |
| Сервис устройства | ограниченные права одного устройства в сеансе |

## Состав продукта

- **Конвертер.** Добавляет к исходнику отдельный слой двух несущих (левая — в левом канале, правая — в правом), измеряет частоты, true peak, LUFS и выдаёт мастер WAV 24 бит, FLAC и QA-отчёт.
- **Магазин приложений.** Каталог RU/EN, карточки, фрагменты, покупка и подписка, библиотека, проигрыватель.
- **Магазин оборудования.** Устройства, комплекты с подбором недостающего, корзина с разделением по продавцам, адреса разных стран, тарифы и индивидуальные предложения, посылки и tracking.
- **Деньги.** Платёжный провайдер через адаптер, неизменяемый журнал проводок, возвраты, выплаты.
- **Сеансы.** Адаптер устройства (симулятор, веб-проигрыватель), проверка L/R, анкеты до и после, измерения с согласием.
- **Интеграции.** REST API с OpenAPI, TypeScript SDK, webhooks.

## Статус на версии 0.2.0

MVP для тестирования. Покрытие разделов ТЗ — на странице продукта «О версии» и в `release.json`. Приёмка по ТЗ v1.0: 35 из 38 критериев passed, 0 failed, 3 not run. Внешние системы (платёжный оператор, перевозчик, кресло, датчики, e-mail) работают через явно помеченные симуляторы; что нужно для production — в `docs/production-dependencies.md`.

## Как устроена работа

- Требования — версии ТЗ в `docs/spec/` (правила в `docs/spec/README.md`).
- Задачи — бэклог (`docs/BACKLOG.md`): интерфейс, сервис, функционал, инфраструктура, интеграции, изменения ТЗ.
- Релизы — `CHANGELOG.md` и `release.json`; каждый релиз указывает версию ТЗ, которую реализует, и закрытые задачи бэклога. Развёрнутый стенд показывает свою версию в подвале и на странице «О версии».
