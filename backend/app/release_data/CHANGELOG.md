# Журнал изменений NAP Store

Формат: [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), нумерация [SemVer](https://semver.org/lang/ru/). До 1.0.0 продукт — MVP для тестирования; 1.0.0 — первый production-релиз. Каждая запись указывает версию ТЗ, которую реализует релиз, и задачи бэклога (`NAP-###`).

## [0.4.0] — 2026-10-31 · реализует ТЗ v1.0

### Исправлено
- «Отправить на модерацию» и решение модератора — казалось, что «ничего не происходит» (NAP-082): запросы выполнялись, но результат был виден только по маленькому значку. Теперь в редакторе приложения на всех вкладках есть баннер «Следующий шаг» (что заполнить, что отправить, сколько ждать, что делать после одобрения или отклонения); на вкладке «Версии и публикация» — чек-лист готовности со ссылками на вкладки, кнопка отправки активна, когда всё обязательное готово; после сохранения, отправки, публикации, отзыва версии — сообщение о результате; в «Описании» — подсказка о несохранённых изменениях (в т. ч. неподтверждённых правах). Модератор после решения видит подтверждение и кнопку «Следующая в очереди».

### Добавлено
- Оценки и отзывы на товары (NAP-079): только после доставки заказа с товаром (метка «Покупка подтверждена», вариант товара), продавец не оценивает свои товары и отвечает из кабинета поставщика (вкладка «Отзывы»), общая очередь модерации; рейтинг на карточках, фильтр «4 и выше» и сортировка по оценке в каталоге устройств; демо-отзывы. Модель отзывов общая для приложений и товаров (миграция 0004).

## [0.3.0] — 2026-10-31 · реализует ТЗ v1.0

### Добавлено
- Оценки и отзывы приложений (NAP-065): 1–5 звёзд, заголовок и текст, привязка к версии и языку; средняя оценка с 5 оценок, распределение по звёздам, средняя по текущей версии; сортировка и фильтры, «Полезно», жалобы. Оценивать могут только пользователи с доступом, для платных — после завершённого сеанса; разработчик не оценивает свои приложения и не может менять, скрывать или удалять отзывы — только публично отвечать (вкладка «Отзывы» в кабинете с фильтрами и динамикой по месяцам). Ссылки, контакты, запрещённые слова и медицинские обещания в ответах уходят на модерацию; очередь «Отзывы и жалобы» у модератора. Рейтинг на карточках, фильтр «4 и выше» и сортировка по оценке в каталоге; демо-оценки.
- Компактная шапка на телефоне (NAP-041): одна строка, кнопка «Меню» с управлением с клавиатуры (Esc закрывает, фокус возвращается).
- Ограничение частоты запросов (NAP-052): общий лимит и отдельные лимиты на ссылки загрузки, части файлов, оплаты, вебхуки, отзывы и конвертации; ответ 429 с текстом на RU/EN и `Retry-After`; настройка `NAP_RATE_LIMITS`. Загрузка частями сама ждёт и повторяет при 429.
- CI (NAP-003): `.github/workflows/ci.yml` — тесты сервера с PostgreSQL/Redis и проверкой миграций, проверки и сборка фронтенда, E2E RU/EN, сборка и запуск Docker Compose, итоговая проверка `ci-ok` для защиты ветки.
- Профиль конвертера «Гамма (40 Гц)», `gamma-40-v1` (NAP-080, параметры заказчика): чистые синусоиды 200 Гц слева и 240 Гц справа, каналы не смешиваются, плавный вход/выход 3 с; QA подтверждает 40 ± 0,1 Гц. Добавляется и в уже развёрнутые демо-базы. Ожидает подписи методистов (NAP-061).
- Контрольная сумма большого файла считается в браузере по частям (hash-wasm), файл целиком в память не читается (остаток NAP-069).

### Исправлено (проверка всех страниц веб-версии: 192 страницы, RU/EN, компьютер и телефон)
- Корзина: товар, которого нет в нужном количестве, подсвечивается, оформление блокируется с понятной причиной (раньше — ошибка после нажатия); появилась кнопка «Убрать», количество применяется по Enter.
- Горизонтальная прокрутка страниц на телефоне: карточка комплекта, редактор приложения, заказ поставщика, профили в админке.
- Подпись отчёта контроля качества была на английском в русском интерфейсе.
- Конвертация больше не отвечает 500, если брокер очередей недоступен: задание остаётся в очереди и отправляется повторно автоматически.
- Внешние ключи `apps` на версию, обложку, превью и комплект отсутствовали в базе (миграция 0003 их добавляет).
- Итог приёмки на странице «О версии» показывался по-английски в русском интерфейсе.

## [0.2.3] — 2026-10-31 · реализует ТЗ v1.0

### Исправлено
- Загрузка аудио больше 10 МБ обрывалась: Next.js пропускает через свой прокси только первые 10 МБ тела запроса, сервер получал обрезанный файл и отвечал ошибкой — трек не появлялся, «Программа» и отправка на модерацию не работали (NAP-069). Файл теперь загружается частями по 8 МБ (`Content-Range`) с докачкой: часть, пришедшая не по порядку, получает 409 с текущим смещением, и браузер продолжает с него. Проверено на MP3 60 минут (86 МБ) через веб-интерфейс.
- Конвертация запускается сама сразу после загрузки с выбранным профилем (галочку можно снять); раньше шаг «Конвертировать» легко было пропустить.
- Первый готовый трек автоматически становится сеансом 1 пустой программы черновика с названием приложения: для одной медитации шаг «Программа» не нужен, его можно только поправить.
- Docker: файл расписания Celery beat перенесён в `var/` — образ работает под непривилегированным пользователем, и `/app` для него недоступен на запись; рабочие файлы beat больше не попадают в репозиторий.
- Вкладка «Аудио и конвертер» разбита на шаги (1. профиль, 2. загрузка, 3. задания), «Программа» объясняет, зачем она нужна.

### Добавлено
- Тест сервера на загрузку частями, докачку и автозаполнение программы; E2E загружает 60-секундный WAV (11 МБ, две части) через прокси Next.js.

## [0.2.2] — 2026-10-31 · реализует ТЗ v1.0

### Исправлено
- «Программа»: сохранение сеанса без выбранного трека давало «Внутренняя ошибка» (500) — пустой идентификатор конвертации не проверялся на сервере (NAP-068). Теперь сервер отвечает 422 с указанием поля (`sessions.N.track`, также для ключа и названий), а форма не отправляет программу, пока у каждого сеанса не выбран трек, и подсвечивает пустой трек.
- Если готовых треков ещё нет, вкладка «Программа» объясняет, что трек появляется после загрузки аудио и конвертации, и ведёт на вкладку «Аудио и конвертер».
- Блок ошибки называет поле программы понятно: «Сеанс 2: трек».

### Добавлено
- Тест сервера на некорректные сеансы программы (всегда 422, не 500) и шаг E2E с сеансом без трека.

## [0.2.1] — 2026-10-31 · реализует ТЗ v1.0

### Исправлено
- «Новое приложение»: адрес с подчёркиванием давал общую ошибку «Проверьте введённые данные» без указания поля (NAP-067). Причина — шаблон `pattern` адреса не компилировался с флагом `v` в современных браузерах (неэкранированный дефис в классе символов), и проверка в браузере молча отключалась.
- Адрес нормализуется при вводе: заглавные буквы → строчные, подчёркивание и пробелы → дефис; недопустимые символы останавливаются в браузере до отправки.
- Блок ошибки называет поле для любых ошибок проверки (`details.field` и `details.fields` в обоих форматах); поле с ошибкой подсвечивается.
- Подсказка к адресу на RU/EN уточнена; поля формы больше не растягиваются по высоте при длинной подсказке.

### Добавлено
- `npm run check-patterns`: все `pattern` в интерфейсе проверяются компиляцией с флагом `v`.
- E2E: сценарий с нелатинским адресом (запрос не отправляется) и адресом с подчёркиванием и заглавными буквами.

## [0.1.0] — 2026-10-31 · реализует ТЗ v1.0

Первая поставка MVP по ТЗ v1.0: приложения и версии с модерацией, настоящий бинауральный конвертер (FFmpeg + NumPy, QA-отчёт), каталог RU/EN, покупки и подписки (Mock + Stripe test), распределение 30/70 с неизменяемым журналом, выплаты и возвраты, магазин оборудования (BOM, склад с резервами, разделение заказов по продавцам, международная доставка Mock/ручная/EasyPost test, посылки, tracking, возвраты), кабинеты разработчика, поставщика, модератора и администратора, сеансы с симулятором кресла и веб-проигрывателем, анкеты и измерения с согласием, TypeScript SDK, OpenAPI, Docker Compose.

Приёмка: 35 критериев passed, 0 failed, 3 not run (Docker Compose в среде без Docker Hub; live-sandbox Stripe и EasyPost без ключей). Подробно — `docs/acceptance-report.md`.
